# Contributing

Before changing app behaviour, open an issue describing the user problem and the proposed scope. Keep pull requests focused. Include a test for note parsing, persistence, or integration changes where it catches a realistic failure.

Run the checks in [README.md](README.md) before submitting a pull request. Never commit API keys, personal vaults, calendar exports, customer data, generated app bundles, or local settings.

Security issues should follow [SECURITY.md](SECURITY.md), not a public issue.
